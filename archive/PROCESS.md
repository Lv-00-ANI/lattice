## 3. 阶段② 编写

### 3.1 新建优先于修改

**默认新建独立文件**（如 `RealXxxExt.lean`），**不动已入库文件**。

**依据**：T1 新建 `RealTemporalLayerExt.lean`（966 行）**零冲突**；
而 A5 的 `RealEffectOrdering` 被**四个版本**覆写（**B216.3**）。

### 3.2 ⚠⚠ **改陈述 vs 改证明体**（**必须区分**）

| 改动 | 后果 | 处置 |
|:--|:--|:--|
| **只改证明体** | 下游**字节级不变** | 可直接改 |
| ⭐ **改陈述** | ⚠ **级联可能** | ⭐ **必须登记 + 改名** |

⭐ **降强度时**必须改名**** ——
⚠ **保留旧名会造成"名字承诺多于陈述"**（**B136**）。

### 3.3 ⭐⭐ **发现假命题时的标准处置**（**五步**）

```
① 构造反例，并逐一核对它【满足原命题全部假设】
② 三分类判定：FALSE / 非反例 / VACUOUS
③ 改陈述为【真但更弱】的命题（不要"调到 error=0"）
④ docstring 逐字登记：原陈述为假 + 反例 + 为何弱化
⑤ ⭐ 把反例【固化为定理】（防复活）
```

**依据**：**B194**（判据 ⑤ 的来源）；A2b 固化 3 条反例（**B210.6**）。

⚠ **三分类的判据**（**最常用**）：
| 反例 | 结论 |
|:--|:--|
| **满足**全部假设 | ⭐ **命题为假** |
| **违反**某假设 | **不是反例**；但若去掉该假设后为假 ⟹ **该假设承重** |
| **某假设本身不可满足** | ⭐ **空洞真** |

### 3.4 ⭐ **"现场推导法"**：把"此路不通"留在代码里

**遇到结构性障碍时，把失败的写法连同证据写进注释** ——
**理由**：**下一个代理会本能地重试**（**A5 的原话，B205.4**）。

**已实践**：A5（`∘` vs `*`）、R9（`ℤ⁰` 的 4 种失败表述）、A9（排除清单）、FT1（`foldBlanks` 论证段）。

### 3.5 ⚠ **禁止事项**（**每条都有事故**）

| 禁止 | 事故 |
|:--|:--|
| ⚠ **`sorry`/`axiom`/`admit`/`native_decide`** | 项目基本纪律 |
| ⚠ **`Set-Content` 写 `.lean`** | **会写 BOM + 毁 UTF-8**（**STYLE.md:854**）|
| ⚠ **裸跑 `lake env lean`** | ⚠ **闸门 `exit 9`**（**B183**）|

### 4.1 ⚠⚠⚠ **"读数与它描述的对象不一致"—— 六个成员**

**这是本项目**最高频**的失误来源**：

| # | 形态 | 登记 |
|--:|:--|:--|

| **2** | **依赖未编译 ⟹ `unknown module prefix` ⟹ 假读数** | **B173** |
| **3** | **日志比源文件旧 ⟹ 描述已不存在的版本** | **B181** |
| **4** | ⚠ **闸门拒绝 ⟹ `exit 9` ⟹ 文件**根本没被检查**** | **B183** |

⭐⭐ **⇒ 强制取证规则**：
> **任何"文件坏了 / 有 N 个 error / 已修好"的陈述，必须附**当次 SHA256 + mtime****。
> ⚠ **否则该陈述在并发环境下**分钟级失效****（**B204.2**）。

### 4.2 ⭐⭐ **`: error:` 精确计数**（**coordinator 自己踩过**）

⚠ **`-match 'error'` 会匹配到 `warning` 文本里的"error"字样** ⟹ **必须用 `': error:'`**。
**依据**：**coordinator 误报 `RealGaussianProcess` "error=1"（实际 0）**（**B204.4**）。

### 4.3 ⭐⭐ **"新旧两名同时 unknown" = 源与 olean 不一致**

⚠ **不要误判为"写错名字"或"phantom cascade"** ⟹ **修法是**重建该模块****。
**依据**：**FT1 最初误判为 phantom cascade，后自我更正**（**B219.2**）。

### 4.4 ⭐⭐ **`unknown constant` 的**四个原因****

① 名字真不存在；② 命名空间错；
③ ⭐ **`import Mathlib` 没覆盖**（**`Mathlib.lean` 是**精选**导入**）；
④ ⭐ **大小写拼错**。

⭐⭐ **⇒ 硬规则**：**凡 `#check` 报 unknown，
先 `grep` `lean/.lake/packages/mathlib/Mathlib/**` 源码** ——
⭐ **源码里写的是什么，就是什么**（**B214.1**）。

### 4.5 ⭐ **信"负面自陈"，不信"正面自陈"**

**本波次的可靠信号排序**：
| 信号 | 可信度 |
|:--|:--:|
| ⭐ **代理主动说"我错了/我撤回"** | ⭐⭐⭐ **最高** |
| ⭐ **代理主动说"未完成/未验证"** | ⭐⭐⭐ |
| **代理说"我修好了"** | ⭐ **须复核** |
| ⚠ **`unused variable` / `exit 9` / warning** | ⭐⭐ **机械信号，最诚实** |

**依据**：A5 撤回自己先验（**B205**）、A4 撤回损坏报告（**B208/223**）、
FT1 撤回 phantom 判定（**B219.2**）、FT2 推翻自己起草的命题（**B223.4**）、

### 4.6 ⭐⭐ **`unused variable` 是"假设写松"的最强机械信号**

⚠ **但候选 ≠ 判定** —— **须区分两种病因**（**B216.4**）：
| 病因 | 处置 |
|:--|:--|
| **假设写松了**（本可承重却没写够）| **补强假设** |
| ⭐ **原稿对载体的语义判断错误** | ⭐ **改写 docstring 说明载体运算** |

**依据**：`RealEffectOrdering` 的 `unused 'h'` —— **真因是 `*` 是逐点乘法而非复合**（**B216**）。

#### 4.6.1 ⛔⛔ **删除之前必须分类：八类（`B424`–`B426`，全库 115 处实测）**

⚠⚠ **`§4.6` 的「最强机械信号」这句话【只对第 1 类成立】** ——
本轮对全库 **115 处**逐站点人工复核后测得：
**48 处（41.7%）带有【书面保留理由】**，**64/115（55.7%）根本不是删除候选**。

| # | 类别 | 判据 | 删除的后果 | 正确处置 |
|--:|:--|:--|:--|:--|
| **1** | **假设** `(h : P)` | `:` 右侧是 Prop | 假设更少 ⟹ **加强** | ✅ **删除** + 调用点检查 |
| **2** | **参数** `(x : E)` | 数据/类型 | **元数改变** ⟹ **另一接口** | ⚠ **接口变更**，须与调用点**一起**改 |
| **3** | **lambda 绑定** | `fun c x =>` | 无物可删 | 改名 `_`（**纯外观**）|
| **4** | **量词内绑定** | `∀ x : E,` 而**体不用 `x`** | ⚠ 不是定理参数 | 写成 `∀ _ : E`（**纯外观**）|
| **5** | ⚠ **假信号** | ⚠ **名字在证明体内【其实被用了】** | ⚠ **毁掉一条定理** | ⛔ **不动** |
| **6** | **已裁定保留** | docstring **记载了保留决定** | ⚠ **覆盖一条已记录的决定** | ⛔ **登记，不删** |
| **7** | **惯例示范** | 文件别处用 `_`，**此处刻意不用** | ⚠ 不用惯例是**更强**的保留信号 | ⛔ **登记，不删** |
| **8** | ⭐⭐ **`WARNING-AS-EVIDENCE`** | 警告**本身就是该定理要传达的缺陷证据** | ⛔ **销毁证据** | ⛔ **绝对不得消除** |

**类别 5 的两个实测实例**（**名字被误报为未使用，实际在用**）：

⭐ **操作规则：`line:col` 锁定的 binder，仍须在【证明体】里 grep 一次，方可采信 linter。**

#### 4.6.2 ⭐⭐⭐ **必要条件：读 docstring，且【不可机械化】**

⛔ **在把任何 `unused variable` 当候选之前，必须先读该声明上方的 docstring 全文。**

⚠ **实测：机械化不可行。** 用「回溯到 docstring + 13 个关键词」扫描
5 个**已知**保留站点，**只命中 1 个（20%）** ——
⭐ **根因有两层**：① 回溯算法定位不到其中 4 个的 docstring；
② **保留的措辞【五种站点五种写法】**（「保留原因」/「诚实定位」/「接口约定」/「语义完整性」/「兼容下游调用」）。
⇒ ⭐⭐ **判据**：**关键词扫描是【排序器】，不是【裁判】。每一条保留裁定都必须有【人工读到的逐字引文】支撑。**
⚠ **且「扫描找不到」【不能】解释为「没有保留理由」** —— 上例 4/5 正是这种情形。

#### 4.6.3 ⭐⭐ **「删除假设 = 加强」的【适用边界】**

⚠ 本规则**不是通则**，本轮被**三次**收窄：
1. **当假设编码的是【陈述所谈论的领域条件】时**，删除**不是削弱命题，而是把它换成一个恰好可证的、不同的定理**
   （`RealRegisterAllocation:196 hloop` —— docstring 逐字：「`hloop` 是**真实的前提**，**去掉它下界不成立**」）；
   ⚠ **该类删除【无法】由「删后仍编译」检出** —— **编译通过与陈述改变可以同时发生**；
2. **即使假设【确实不承重】，它仍可能是【一条已记录的保留决定】**
   （`RealFCAImplicationBasis:249` —— 前一轮**跑过同一个实验**、看到同一条警告、
   把该警告**写进 docstring 当作证据**、判定它不承重、**却仍为语义完整性保留**）；
3. ⭐ **若【保留的另一个假设更强且蕴含被删者】，则删除是真加强**
   （`RealHeadPruningOptimal:314`：保留的 `1 + c·D₂ < 0` **蕴含** `c < 0`）。

⇒ ⭐ **合起来的判据**：**一个 `unused variable` 是否为缺陷，不能由①②③任一项单独判定，必须加④读 docstring。**

#### 4.6.4 ⚠ **警告【移动】是诊断信号，不是麻烦**

⚠ **删参数会【级联】**：使**调用者自己的**假设变成未使用，**警告【移动】而非消失**。
⭐ **实测两例**：删 `hloop` ⟹ 警告移到 `inLoop`；删 `hdown` ⟹ 警告移到 `Rel`。
⇒ **判据：警告移动时应【重读】，而不是【追着补齐】；且【必须查它是 GONE 还是 MOVED】。**

#### 4.6.5 ⚠ **行尾陷阱：混合行尾会让【多行编辑静默失效】**

⚠ 本仓**同时存在**纯 LF、纯 CRLF 与 MIXED 文件（实测 `RealInformationGeometry`/`RealEditCrosstalk`/
`RealAdam`/`RealNormStability` 为 **CRLF**；`CORRECTIONS.md` 为 **MIXED**）。
⚠ **用裸 `\n` 写的多行匹配模式，在 CRLF 文件上【匹配不到】（`count=0`），尽管内容完全相同。**
⇒ ⭐ **判据**：**`count == 1` 守卫混淆了两种失败** ——
`count > 1` 是**歧义**（可安全拒绝）；**`count == 0` 有三种成因**（已修过 / 模式文本写错 / **行尾不匹配**）
⟹ **必须【诊断】，不得当作「不存在」**。**正解：先归一化行尾，再让 `0` 表示真正的缺失。**


### 4.7 ⭐⭐⭐ **CALIBER RULE：凡陈述一个计数，必须给【口径 / 时刻 / 范围】**（**B418/B419**）

|--:|:--|:--|
| **①** | **口径 = 集合 + 谓词** | 「4 个非孤儿」**无意义**；「在 `roots` 集合上、谓词 = 真实 `import` 边、有 4 个模块 in-degree ≥ 1」**才是陈述** |
| **②** | **采样时刻** | 有并发写者时，**计数是【时变量】而非结构常量**；无法标注时刻的，**标「不可验证」** |
| **③** | **范围** | 须说明是否受**部分构建 / 部分扫描**限制。⚠ **实测偏差达一个数量级**（局部 5–6 vs 全量 **157**）|
| **④** | ⭐⭐ **零值对照** | 报「**0 命中**」**之前**，**必须**先用**已知为真**的对照物验证工具本身 |
| **⑤** | **两法互证** | 关键计数用**两种独立方法**测；**分歧必须报告**，**不得静默取一** |
| **⑥** | **主语核对** | 引用一个**既有**计数前，先核对其**主语** |

**④ 为什么最重要**（**B418 亲历**）：其第一版探针**两个 CASE 都返回沙箱管道垃圾码
`rc=4294770688`** —— **看起来像「两个都跑了」，实则【什么都没跑】**。
> ⭐ **没有【对照物】时，「通过」与「工具坏了」【不可区分】。**
> ⚠ 而**「报 0 的扫描器」看起来像「确实没有」，不像「坏掉了」** ——
> **这是一个【静默】的失败方向**，故必须用对照物把它变成**响**的。

**⑥ 的两个实例**：
- `B414`：`DIVERGENCES` 里的「**13**」是**跨目录合计**（4 `_probe_out` + 5 `_r9` + 1 `scripts`），
  **不是 `_r9` 的条数**；
- `B419`：B-27 的「**5 个文件**」是**另一个假设 `hxdom`** 的分布（`CORRECTIONS:1586` 逐字
  「19 条互相之间传 `hxdom`」）—— **被替换的假设的分布 ≠ 替换品的分布**。

⚠ **反向陷阱（`B419` 发现）**：**「两口径差很大」这句话本身也必须带口径。**
协调者曾把「in-degree 两口径差约 2 倍」当**通用警告**反复传播；
实测 **roots 252/519 = 48.6% vs 顶层非下划线 255/522 = 48.9%（比 1.01）**，
**计入 `_*` scratch 才升至 329/601 = 54.7%（比 1.31）** ——
⭐ **「约 2 倍」在【任何】集合上都得不到支持**（它属于**另一批量**：具体配对数）。
> ⭐ **一个人们【以为差很大、实际差很小】的口径，与相反的陷阱【同样有害】。**

⚠ **且「计数」≠「缺陷数」**（`B418`）：全量构建 **386** 条警告中，
`unused section variable` **173** 条**不是** `§4.6` 信号（Lean **自动纳入文件级 `variable`**，
「本定理未用」是**常态**）；`unused variable` **157** 条中**只有 131 条是签名假设**。
**不得**把 386 说成「386 个已知缺陷」。

## 5. 阶段④ 注册 + 阶段⑤ 构建：**并发控制**

### 5.1 ⭐⭐ **批处理是唯一杠杆**

⚠ **单文件探针在竞争环境下成功率约 1/50 ~ 1/250**（**A5 的实测，B213.6**）⟹
⭐ **⇒ 必须**合并 N 个目标成一次 `lake-lock.ps1` 调用****（**一次队位**）。

**依据**：**B193**。**本波次最大一次：7 模块一次队位**（**B212**）。

### 5.2 ⭐⭐ **归因：祖先链不能定罪，**直接父进程命令行**可以**

**原表述（已修正）**：
> ⚠ **"从父链**无法**判定是哪个 agent 绕锁"**（**B184**）

⭐⭐ **⇒ 修正**（**Q3 用进程命令行实测得出，B233**）：
> ⚠ **祖先链是共享的**（**从 `node.exe` 往下大家都一样**）⟹ **祖先**不能**定罪；
> ⭐ **能定罪的是「`lake`/`lean` 进程的**直接父进程**」**：

| 形态 | 判据 |
|:--|:--|
| ✅ **合规** | **`lake.exe <- powershell.exe(pid)` 且该 powershell 跑的是 `lake-lock.ps1`** |
| ⚠ **绕锁** | ⭐ **`lake.exe <- powershell.exe(pid)` 且该 powershell 是 `-Command "… lake env lean …"`** |

⭐ **⇒ 判据 = 取 `lake`/`lean` 的**直接父进程的 `CommandLine`**，**而非整条祖先链**。**

⚠ **⇒ 且**不要"掐掉绕锁者"**（**会连带杀死共享祖先的其他代理**）——
⭐ **⇒ 正确处置是**让它自己停**（**已多次通过公告生效**）**。

### 5.2b ⚠⚠ **一条裸命令会**使所有代理的读数失效****

⭐⭐ **⇒ `probe.ps1` 是 **fail-closed** 的**：
**只要有任何裸 `lake env lean` 存活，它**拒给读数**（`exit 9`）** ⟹
⭐ **按 §4.1 第 ④ 条，`exit 9` = **该文件根本没被检查**** ⟹
⭐⭐ **⇒ 所以"绕过锁"**不只影响自己**，**它污染所有其他代理的读数**** ✓

⚠ **⇒ 且更深的风险**：
- **无锁读者**可能看到**半写的 olean** ⟹ **报幻影错误**（**B167**）
- **无锁写者**可能**损坏共享构建目录**

⭐⭐ **⇒ 判据**：**"要求别人走锁"与"自己走锁"必须由**同一机制**保证，
**不能靠记性** —— ⭐ **⇒ 必须让**正确做法比错误做法更省事****
（**`scripts/lean_probe.py`：一次队位跑 N 个模块，**比逐个裸跑更快**）**。

### 5.2d ⚠⚠ **查看编译输出**只能走锁**（coordinator 的两次违规）**

⭐⭐ **⇒ 硬规则**：
> **凡查看任何 `.lean` 的编译输出，只用**：
> ```
> python scripts\lean_probe.py lean\<File>.lean      （批量走锁，一次队位）
> powershell -File scripts\probe.ps1 <File>.lean     （单文件走锁）
> ```
> ⚠ **绝不写 `lake env lean` —— **即使"只是想看一眼"****。**

⚠ **⇒ 为什么写成硬规则**：**coordinator **两次**因"只想快速看一眼"而绕锁**
（**B233 / B257**），**且它在第一次之后**已经承诺过改正**** ⟹
⭐ **⇒ "承诺"不是机制** ⟹ **只有**写进文件 + 修好工具**才算** ✓
⚠ **⇒ 而"修好工具"是指**：`lean_probe.py` 曾被发现**对失败的批次报 clean**
（**R5**）—— ⚠ **一个会撒谎的工具是没人会用的工具** ⟹ **修好后它才真正可用** ✓
### 5.2c ⚠⚠ **"文本中存在" ≠ "生效" —— 必须取**运行期证据****

⭐⭐ **⇒ 本波次**两次**踩到同一形态（**B237 / B239**）**：

### 4.7.1 ⛔ **裁决：口径判据对【真实报告】永久保持【建议性】，不转阻断**（`B426`）
