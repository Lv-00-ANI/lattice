docs: PLUGIN-SYSTEM -- the plugin system as part of the proof

Adds the plugin-system design document: what the system is, what Lean
proves, what C implements, and the two sides share one manifest.

## The central claim

The plugin system is PART OF the proof, not a framework outside it.
Ownership, dependency, obligation, conflict, version, params, retrieval
and orchestration are each machine-checkable propositions.

Eight roles, one theorem each:
  implements_eq_offered / requires_acyclic / obligations_resolve
  decl_before_key / compat_trans / merge_last_wins
  traversal_independent / Q1-Q18

Orchestration is the eighth role, not the whole system.

## Three additions this round

3.5 capability exposure model. "Expose everything" and "retrieval
returns a unique answer" conflict directly: the same capability exists
in 6 copies (vector encoding), 3 (softmax), 10 (residual definitions).
Resolution is three tiers -- protocol tier (winner only, default),
implementation tier (losers, explicit open), negation tier (always).
Every proved proposition is visible in SOME tier; retrieval stays unique.

10.8 C-side runtime check scope. C checks ONLY what cannot be decided
statically -- file existence, dynamic linking, allocation, symbol
resolution. Everything else is a build-time gate. Rationale: one rule
with two implementations is one rule that will drift.

G.7 archive-layer cut order. Three stages, order not reversible:
22 stale comment paths (zero risk) -> 29 imports (medium) ->
42 named files (high).

## New dimension: integration (5.6)

Tier (primitive/composition) is decided by requires. "Isolated" is a
separate dimension: a plugin can be composition-tier and still have no
consumer. Adds integration: linked | standalone | unlinked, report-only
for unlinked. One hard rule: the combinator layer must have at least
one integration = linked.

## Bootstrap (appendix I, was open item U5 -- now decided: required)

Without bootstrap the loader is a trust base outside the proof.
loaderPrim : Primitive (List Manifest) LoaderState -- run is the C
implementation, sound is the Lean proof. Three steps: static loader
correctness, self-loading, convergence (Q18).

One boundary must be recorded, not argued away: C-side loadAll is not
pure (malloc/free), so convergence holds on the Lean side only. C can
prove observable equivalence (B-C1), never side-effect-sequence
equivalence (B-C2).

## Roadmap (appendix J)

Three layers, order not reversible:
  coarse      -- Real* prefix, dir decides ownership, imports decide deps
  structural  -- write plugin.yml, decide tier, check composition ratio
  semantic    -- rename to semantic prefixes, converge duplicates,
                 build three-tier exposure, remove archive layer

The layer order matters: you cannot decide "same protocol?" before
plugin.yml exists, and you cannot decide "who is winner?" before the
slots are filled.

The first action is NOT writing plugin.yml. It is fixing 12 S-level
defects -- while verify_all rewrites its own inputs, while two
--self-test bodies are shells, while three rank tables disagree, no
structural pass can be verified.
